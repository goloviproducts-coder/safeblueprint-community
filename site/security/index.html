Security

What this beta does to protect a visit. It is not a certification.

How we protect you

  • The tool runs in your browser. The checks do not need an account.
  • No accounts, storage, cookies, or tracking. Answers are not written to storage and are not sent with the page.
  • No outbound posts. The self-hosted edition has no forms that send data and no server relay.
  • No third-party scripts. Scripts and styles are files on this site. The print footer is a stylesheet the browser builds for the reference and classification. It is not loaded from another site.
  • Offline support caches only site files. The service worker does not cache what you type or a form post.

What we never collect

  • Your answers, notes or organisation name.
  • Question packs or files you load.
  • Your reports or exports.
  • Cookies, analytics, tracking pixels, fingerprints or advertising IDs.
  • An account, login or password. There are none.

The only content of yours that leaves your device is a contact form message you choose to send, after you consent. Like any website, the host still sees normal request data such as your IP address and browser type when you load a page. Anyone can check this with the open-source privacy proof test, which runs the whole tool and every export and fails if any request goes to another site.

Protections in place

  • Strict Content-Security-Policy on the response, with no unsafe-inline. Scripts are same-origin files. Styles are same-origin files, plus a blob stylesheet used only for the print footer reference and classification.
  • HSTS: max-age 63072000, includeSubDomains, preload.
  • Permissions-Policy denies camera, microphone, geolocation, payment, USB, and interest-cohort.
  • Cross-Origin-Opener-Policy and Cross-Origin-Resource-Policy are same-origin.
  • X-Frame-Options DENY, and CSP frame-ancestors none on the response header. The meta policy does not repeat frame-ancestors, because a meta element ignores it.
  • X-Content-Type-Options nosniff.
  • Referrer-Policy strict-origin-when-cross-origin.
  • Subresource Integrity (sha384) on local CSS and JavaScript.
  • Output escaping. Names and other text you type are written as text, not as HTML.
  • CSV and TSV formula-injection guard. A cell that starts with =, +, -, @, a tab, or a carriage return is prefixed with a quote.
  • Input limits, and control characters are stripped.
  • Honeypot and a three-second wait before the first form submit.
  • The repository is private. A release is reviewed before it is published.

Open source and continuous scanning

The code is public on GitHub under Apache-2.0. Changes to the main branch go through a pull request. Each pull request runs a checksum check plus CodeQL, Semgrep, Gitleaks, Trivy, dependency review and a GitHub Actions check. Secret scanning with push protection is on.

The repo's OpenSSF Scorecard results are public. From v1.0.0, release checksums and build attestations are available on the releases page. Signed releases are being added.

You can also report a vulnerability privately through GitHub security advisories. See the repo's Security tab.

Threat model summary

There are no accounts to spoof. The contact form is the only contact route, and the mailbox is not in the source. Pages load only same-origin CSS and JavaScript, with subresource integrity, and user text is not assigned as HTML. A form post is a message you chose to send. The site does not keep a server-side audit log. Initiative names and answers stay in memory for the visit. They are not put in storage, cookies, or the address. Copy tasks leaves the initiative name out. A playbook summary, if you tick the optional box, does not include that name. Form spam is limited by a honeypot, a short wait, length limits, and the same checks on the relay. There is no role to escalate. The service worker caches listed site files only. The notes for models are our own static description, not a channel a visitor can write to. This summary is not a penetration test.

Report a vulnerability

Use the contact form. Include the page, what you saw, and how to reproduce it. Do not include passwords or customer data. The contact file for researchers is /.well-known/security.txt.

Good-faith research that avoids privacy harm, downtime, and other people's data is welcome. We will not take legal action over that research. Please tell us first and give us a reasonable time to fix the issue before you publish details.

In short

  • Answers stay in this browser.
  • Forms post only to this site, after consent.
  • The mailbox is not on the page.
  • This page is not a certificate.
