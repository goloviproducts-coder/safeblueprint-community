# Release notes template

Release notes are short, plain-English bullets for executives. Use these six headings, in this order, in CHANGELOG.md under the new version. The release workflow copies that section into the GitHub release.

```
## [X.Y.Z] - YYYY-MM-DD
### Features
- What people can now do
### Issues fixed
- What was wrong and is now right
### Interfaces updated
- Pages, screens, editions or guides that changed
### Security fixes
- Protections added or weaknesses closed
### Privacy
- How user data handling changed
### General
- Licensing, docs, project housekeeping
```

Rules:
- One line per bullet, no jargon, no PR numbers needed.
- Write "None" under a heading with nothing to report.
- No penalty amounts, no legal advice, no email addresses.
